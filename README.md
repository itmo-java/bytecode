# Лабораторная работа № 3: анализ байткода JVM

## Цель

Познакомиться с байткодом JVM и научиться работать с ним, извлекать информацию о программе *без ее запуска*. Спроектировать анализатор `.jar`-файлов, собирающий ниже приведенные метрики.

## Задание

Разработать консольную Java-программу для статического анализа байткода Java-проектов по приведенным метрикам, возвращать результаты текстом в консоли и в формате JSON-отчета. Анализ должен выполняться без запуска исследуемого приложения и без загрузки его классов через Reflection. Опробовать получившуюся программу на примерах `.jar`-файлов из директории `src/main/resources`.

Приложение должно:
1. Принимать на вход проект в виде `.jar`-файла.
2. Анализировать содержащиеся в нём `.class`-файлы.
3. Вычислять перечисленные ниже метрики.
4. Выводить результаты в консоль и сохранять их в файл в машинно-читаемом формате JSON.

Для анализа байткода можно использовать эти и другие инструменты:
- **ASM** — библиотеку для чтения и модификации байткода JVM.
- `java.lang.classfile` API — стандартный API Java, доступный начиная с JDK 24.

## Обязательные метрики

### 1. Максимальная глубина наследования

Максимальная глубина иерархии наследования среди классов анализируемого проекта.

### 2. Средняя глубина наследования

Средняя глубина иерархии наследования среди классов анализируемого проекта.

Для обеих метрик учитывается наследование внутри анализируемого JAR. Если родительский класс отсутствует в JAR, его наследник считается корневым (глубина 0).

### 3. Метрика ABC

Метрика ABC определяется тремя компонентами:

- **A (Assignments)** — количество инструкций изменения локальных переменных: `ISTORE`, `LSTORE`, `FSTORE`, `DSTORE`, `ASTORE`, `IINC`.
- **B (Branches)** — количество инструкций вызова: `INVOKEVIRTUAL`, `INVOKESTATIC`, `INVOKESPECIAL`, `INVOKEINTERFACE`, `INVOKEDYNAMIC`.
- **C (Conditions)** — количество инструкций условного перехода (`IF*`, `IFNULL`, `IFNONNULL`), а также `TABLESWITCH` и `LOOKUPSWITCH`.

Каждая инструкция `switch` учитывается как одна операция. `IINC` не считается assignment в рамках этого задания.

Итоговое значение:

`ABC = sqrt(A² + B² + C²)`

Необходимо вычислить компоненты ABC и итоговое значение для каждого класса и для проекта целиком.

Учитывать все методы, содержащие байткод, включая конструкторы и статические инициализаторы.

### 4. Среднее количество переопределённых методов

Среднее количество методов, объявленных в классе и переопределяющих методы предков либо реализующих методы интерфейсов.

Учитывать только предков, информация о которых доступна в анализируемом JAR.

Перегрузка метода не считается переопределением. Конструкторы, статические, приватные, `synthetic` и `bridge`-методы не учитываются.

### 5. Среднее количество полей в классе

Среднее количество полей, непосредственно объявленных в классах анализируемого проекта.

Учитывать статические и нестатические поля, включая поля, сгенерированные компилятором.

## Требования к реализации

- Приложение должно анализировать все обычные классы из переданного JAR, в том числе абстрактные классы, `enum` и `record`.
- Интерфейсы участвуют в определении переопределённых/реализованных методов, но не включаются в расчёт средних метрик по классам.
- `module-info.class` и `package-info.class` не учитываются.
- Приложение должно корректно обрабатывать ошибки ввода, чтения JAR и записи результата.
- Отчёт должен содержать как агрегированные метрики проекта, так и метрики отдельных классов.
- Формат JSON и интерфейс командной строки определяются самостоятельно.

Поддержка multi-release JAR не обязательна.

На защиту работы:
1. Исходный код приложения.
2. Краткий гайд по сборке и запуску, возможностях программы.
3. JSON-отчеты по примерам из директории `src/main/resources`.
4. Тесты для проверки корректности вычисления метрик.
