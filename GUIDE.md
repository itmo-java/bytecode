# Анализатор байткода

Консольная программа читает `.class`-файлы из JAR с помощью ASM, вычисляет пять обязательных метрик и сохраняет JSON-отчёт. Исследуемые классы не загружаются в JVM, их конструкторы и статические инициализаторы не выполняются. Зависимости исследуемого проекта устанавливать не требуется.

## Сборка и запуск

Нужен **JDK 21**. Gradle 8.14 загружается через включённый wrapper; отдельная установка Gradle не нужна. При первой сборке нужен доступ к Gradle и Maven Central.

```bash
./gradlew clean build
./gradlew run --args="src/main/resources/sample.jar reports/sample.json"
```

В Windows используйте `gradlew.bat` вместо `./gradlew`.

Для запуска без Gradle после сборки:

```bash
./gradlew installDist
build/install/bytecode/bin/bytecode src/main/resources/sample.jar reports/sample.json
build/install/bytecode/bin/bytecode --help
```

В Windows команда имеет вид `build\install\bytecode\bin\bytecode.bat`. Для путей с пробелами заключайте каждый путь в кавычки. Переносимый ZIP с программой и зависимостями создаётся в `build/distributions/`.

Аргументы: `bytecode <input.jar> [output.json]`. Если второй аргумент отсутствует, файл `<имя>.report.json` создаётся рядом с JAR. Отсутствующие каталоги отчёта создаются автоматически. Существующий отчёт заменяется после успешного анализа и записи временного файла; входной JAR перезаписать нельзя.

Коды завершения: `0` — успех или справка; `1` — ошибка чтения/анализа/записи; `2` — ошибка аргументов. Сообщения об ошибках выводятся в stderr, отчёт — в stdout. Повреждённый класс прерывает весь анализ с указанием его пути, чтобы не выдавать частичные результаты за полные.

## Метрики и границы анализа

| Метрика | Правило |
| --- | --- |
| Глубина наследования | Только цепочка суперклассов внутри JAR. Если непосредственного родителя нет в JAR, глубина равна 0. Интерфейсы глубину не увеличивают. |
| Средняя глубина | Сумма глубин / число обычных классов, включая абстрактные, вложенные, анонимные, `enum` и `record`. |
| ABC: A | `ISTORE`, `LSTORE`, `FSTORE`, `DSTORE`, `ASTORE`, в том числе компактные и `wide`-формы. Запись полей и элементов массивов не учитывается. |
| ABC: B | `INVOKEVIRTUAL`, `INVOKESTATIC`, `INVOKESPECIAL`, `INVOKEINTERFACE`, `INVOKEDYNAMIC`. |
| ABC: C | Все условные `IF*`, включая `IFNULL`/`IFNONNULL`; каждый `TABLESWITCH` или `LOOKUPSWITCH` считается один раз, независимо от числа веток. `GOTO` не учитывается. |
| Переопределения | Считаются только методы, непосредственно объявленные в классе, для которых найден доступный метод предка или интерфейса внутри JAR. Один метод считается один раз, даже при нескольких совпавших предках. |
| Поля | Все непосредственно объявленные поля: статические, экземплярные и сгенерированные компилятором. Унаследованные поля не добавляются. |

В условии `IINC` сначала указан в перечне A, но далее явно исключён. Реализация следует явному исключению: **`IINC` не входит в A**.

ABC считается по всем методам с байткодом, включая конструкторы, статические инициализаторы, приватные, синтетические и bridge-методы. Для проекта сначала суммируются A, B и C, затем вычисляется `sqrt(A² + B² + C²)`; значения ABC отдельных классов не складываются.

Интерфейсы и аннотации вынесены в отдельный раздел `interfaces`; они участвуют в поиске переопределений, но исключены из количества обычных классов и всех средних метрик. Их байткод, например `default`- и статические методы, включён в ABC проекта, поскольку это не средняя метрика по классам. Для пустого JAR и JAR только с интерфейсами средние метрики равны 0.

При поиске переопределений учитываются имя и типы параметров, а не возвращаемый тип, поэтому ковариантный возврат не теряется. Проверяется доступность `public`, `protected` и package-private методов; методы другого пакета без модификатора доступа не учитываются. Конструкторы, статические, приватные, synthetic и bridge-методы исключены из числа переопределений. При generics bridge-метод используется только для связи стёртой сигнатуры предка с реальной реализацией: сам bridge отдельно не считается. Методы внешних предков, например `Object.toString()`, не учитываются, если этих предков нет в JAR.

Читаются все `.class`-записи внешнего архива, включая нестандартные пути вида `project/module/target/classes/…`; полное имя берётся из байткода. Вложенные JAR рекурсивно не раскрываются. `module-info.class`, `package-info.class` и `META-INF/versions/…` пропускаются. Multi-release JAR анализируется только по базовым классам. Два определения одного полного имени класса считаются ошибкой, а не молча перезаписывают друг друга.

## Формат JSON

Отчёт в UTF-8 содержит:

- `inputJar` — имя входного файла без абсолютного пути;
- `project` — количество классов и интерфейсов, максимальную и среднюю глубину, средние количества переопределений и полей, ABC проекта;
- `classes` — имя, вид (`class`, `abstract`, `enum`, `record`), глубину, количество переопределений и полей, ABC каждого обычного класса;
- `interfaces` — имя, количество полей и ABC каждого интерфейса/аннотации.

ABC везде представлен объектом с полями `assignments`, `branches`, `conditions`, `value`. Типы отсортированы по полному имени. Отчёт не зависит от текущего времени, абсолютного пути и локали. В JSON сохраняется полная точность `double`, в консоли значения округляются до шести знаков.

## Проверка

```bash
./gradlew test
./gradlew sampleReports
```

Первая команда запускает JUnit 5; HTML-результат находится в `build/reports/tests/test/index.html`. Тесты компилируют небольшие Java-примеры и генерируют точные наборы инструкций через ASM: проверяются все обязательные opcodes, наследование, интерфейсы, перегрузки, видимость, generics, ковариантный возврат, поля enum/record, отсутствие выполнения кода, ошибки ввода и JSON-вывода. Kotlin-пример из задания проверяется отдельно по известным метрикам.

Вторая команда заново создаёт `reports/sample.json`, `reports/fescar.json`, `reports/guava.json`. CI запускает сборку, тесты и генерацию отчётов и проверяет, что результаты совпадают с сохранёнными файлами.

## Структура реализации

- `Main` — аргументы, коды завершения и ошибки пользователя.
- `JarAnalyzer` — чтение архива без загрузки исследуемых классов.
- `ClassMetricsVisitor` — сбор метаданных и подсчёт инструкций ASM.
- `MetricsCalculator` — обход доступной иерархии и агрегация.
- `model` — неизменяемые объекты отчёта.
- `ReportWriter` — консоль и JSON через Gson.
- `SampleReports` — воспроизводимая генерация трёх обязательных отчётов.

Учебные `Example`, `ClassPrinter`, `ByteCodePrinter` из шаблона сохранены. Основная точка входа готовой программы — `org.example.Main`. Дополнительные задания с Java Agent и сравнением API не реализованы.
